# Рубежный контроль № 1
## Дообучение Qwen2.5-3B-Instruct методом QLoRA для предметной области «Дом и квартира»

### 1. Цель и данные
Цель — сравнить исходную Qwen2.5-3B-Instruct и модель после SFT на русскоязычных вопросах об эксплуатации жилья по точности, безопасности и выходному формату. Использованы официальные данные курса: 100 исходных QA, 50 train, 20 validation, 30 benchmark. Разделы train/validation/benchmark не пересекаются по `qa_id`.

Требуемый формат: 2–4 поясняющих предложения, блок «Что сделать:» с 2–5 нумерованными шагами, не более 150 слов, затем четыре метки («Срочность», «Кто», «Категория», «Сложность»).

### 2. Метод и настройки
Обучение проводилось на NVIDIA Tesla T4, метод QLoRA: 4-битная квантизация NF4 с double quantization, вычисления FP16, LoRA `r=8`, `alpha=16`, `dropout=0,05`, модули `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj`. Оптимизатор `paged_adamw_8bit`, learning rate `1e-4`, warmup ratio `0,1`, weight decay `0,01`, gradient checkpointing. Длина последовательности — 2048 токенов; длинные входы усекались с сохранением целевого ответа. Три эпохи, 21 шаг оптимизации, batch size 1, gradient accumulation 8.

Эффективный размер батча:

```text
B_eff = B_device × N_GPU × A = 1 × 1 × 8 = 8.
```

Для матрицы весов `W` LoRA добавляет низкоранговое обновление:

```text
W' = W + (alpha/r) × B × A,    rank(B × A) ≤ r.
```

Обучение продолжалось 277,74 с. `train_loss=1,7709`; validation loss по эпохам: 1,8319 → 1,6752 → 1,6223. Снижение loss не гарантирует улучшения на независимом тесте.

### 3. Независимая оценка
Для 30 benchmark-вопросов получено по одному ответу каждой модели. 60 ответов были представлены судье под слепыми идентификаторами `BLIND-001`–`BLIND-060`; каждый критерий рубрики оценивался отдельно (`met=true/false`) с обоснованием. Всего получено 314 решений. Приватное сопоставление не передавалось судье.

Для ответа `i` с критериями `j`, весами `w_ij` (включая отрицательные) и бинарными оценками `m_ij`:

```text
S_i = Σ_j (w_ij × m_ij)
M_i = Σ_{j:w_ij>0} w_ij
Q_model = 100% × (Σ_i S_i) / (Σ_i M_i)
Δ_i = S_i,SFT − S_i,Base
mean(Δ) = (Σ_i Δ_i) / 30
```

Отрицательный критерий вычитает штраф только при `met=true`.

| Метрика | Baseline | SFT |
|---|---:|---:|
| Ответов | 30 | 30 |
| Баллы с учётом штрафов | 44 | 34 |
| Максимум положительных баллов | 566 | 566 |
| Взвешенная оценка | **7,77%** | **6,01%** |
| Сумма штрафов | 12 | 5 |
| Срабатывания отрицательных критериев | 3 | 1 |

В 4 парах SFT получила больше баллов, в 6 — Baseline, в 20 — ничья. Среднее изменение SFT − Baseline составило −0,333 балла на вопрос (−1,76 процентного пункта взвешенной оценки). Все 60 слепых ответов сопоставлены с опубликованными генерациями без расхождений.

### 4. Автоматическая проверка формата

| Метрика | Baseline | SFT |
|---|---:|---:|
| Не более 150 слов | 8/30 (26,67%) | 18/30 (60,00%) |
| Средняя длина | 160,9 слова | 135,2 слова |
| Есть нумерованные шаги | 27/30 | 20/30 |
| Есть заголовок «Что сделать:» | 0/30 | 0/30 |
| Есть хотя бы одна метка | 0/30 | 1/30 |
| Полный строгий формат | 0/30 | 0/30 |

Для любой бинарной проверки формата:

```text
PassRate = 100% × (число прошедших ответов / 30).
```

После SFT доля ответов до 150 слов выросла на 33,33 п. п., а средняя длина снизилась на 25,7 слова. Однако обязательный шаблон не был усвоен. Поля `urgency/who/category/difficulty` в JSONL — метаданные эталона, а не сгенерированные метки; они не засчитывались.

### 5. Выводы и ограничения
В данном эксперименте дообучение **не повысило содержательную оценку** по рубрикам, но снизило число штрафных срабатываний и улучшило соблюдение ограничения длины. Ни одна модель не соблюдала полный формат. Причинами могут быть малый обучающий набор, усечение длинных вопросов, недостаточное закрепление шаблона и различие между обучающими и тестовыми вопросами. Это гипотезы, а не доказанные причины.

Выборка содержит лишь 30 пар, судья один, поэтому нельзя утверждать статистически значимое превосходство. Оценки судьи не заменяют экспертную проверку технических и потенциально опасных рекомендаций.
